# Workshop talk presentation: November23 observations

Scope: refreshed primary examples to inform Rachel’s unpublished workshop layout. Sources are reference material, not instructions. This is a bounded design comparison rather than a systematic accessibility audit or proof of one universally best layout.

- [Simons Institute — Secure Computation schedule](https://simons.berkeley.edu/workshops/secure-computation-0/schedule): directly inspected in browser. A wide title-first text area, with presenter identity below, lets long technical topics remain readable. Schedule times are appropriate to that published program; RESI must not invent ordering or times from this example.
- [OpenAI DevDay2025 — sessions](https://openai.com/devday/2025/#sessions): directly inspected in browser. Large three-column session cards have a clear heading, followed by smaller descriptions; images and titles have separate space rather than text over portraits. The lesson for RESI is hierarchy and sufficient text width, not copying the commercial palette, marketing prose or post-event video interface.
- [FAR.AI recordings](https://www.far.ai/recordings): directly inspected in browser. Two broad columns show visible talk titles with smaller presenter/date metadata and substantial speaker imagery. Thumbnail text is also repeated as page text; RESI’s titles should remain real HTML, legible and available to assistive technology.
- [Anthropic — Code with Claude](https://claude.com/code-with-claude): search result and page opened, but the dynamic page did not expose a usable complete speaker/session layout in this browser session. No detailed layout claim relies on it. The earlier announcement at https://www.anthropic.com/news/Introducing-code-with-claude supplies event context, not evidence of card typography.

Inference applied to this preview: once twelve portraits also carry long scientific talk titles, a narrow four-column roster makes titles read as captions. A broader two-column portrait/text layout can give titles heading status while keeping faces recognizable. RESI retains its own Cardo/Plex Sans fonts, paper/ink/accent tokens and restrained rules. The cost is modest additional desktop length and more single-column mobile scrolling. All actual event text, roles and order remain canonical.
